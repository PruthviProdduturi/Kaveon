# Typed aggregate exchange count-overflow qualification — 2026-10-18## ScopeThe columnar typed partial-state exchange now checks `u64` row-count accumulation for `COUNT`, floating `SUM`/`AVG`, and integer `SUM` before mutating the accumulator. A wrapped count could otherwise corrupt a distributed result or panic in debug builds when a worker partial was merged into a saturated coordinator slot.## EvidenceCommand:```textcargo test -p kaveon-exec count_overflow -- --nocapture```Result: 2/2 focused tests passed.- `floating_partial_merge_rejects_count_overflow_without_mutating_state` verifies scalar state merge rejects `u64::MAX + 1` for `SUM`, `AVG`, and `COUNT`, preserving the original state.- `typed_partial_sum_merge_rejects_count_overflow_at_exchange_boundary` encodes two grouped partial batches, routes them through `IncrementalAggregateMerger`, and verifies the typed columnar exchange returns `floating aggregate count overflow` instead of wrapping or panicking.The same checked-count invariant is applied to integer `SUM` in both row and compact columnar merge paths. Normal finite partials retain the existing merge behavior.## BoundaryThis qualifies fail-closed count accumulation during typed partial exchange. It does not claim overflow protection for source-row ingestion counters or floating-point sum overflow; those remain separate numeric contracts.
